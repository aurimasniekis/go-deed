# Versioning

- Deed releases use SemVer `vX.Y.Z`. The changelog follows Keep a Changelog 1.1.0.
- The API version is the URL prefix: `/api/v1`. Within v1 changes are **additive only**: new endpoints, new optional
  request fields, new response fields, new enum values in responses (clients must ignore unknown fields and treat
  unknown enum values as "other").
- Breaking changes go to `/api/v2`, served alongside v1 for at least one MINOR release with a deprecation notice in
  the OpenAPI document and a `Deprecation` response header.
- The committed `api/openapi.json` (OpenAPI 3.1, generated by `deed openapi`) is the contract; CI fails on drift.
- Contract elements beyond the schema: bearer token formats (`deed_at_`, `deed_st_`), `Idempotency-Key`,
  `ETag`/`If-Match` (412 on mismatch), RFC 9457 problem `code` values, pagination cursors (opaque), SSE event names
  and `Last-Event-ID` semantics, Pulse event subjects/types (`deed.*.v1`; a breaking payload change gets `.v2`).
- Resource model: `apiVersion: deed.dev/v1`. Custom kinds version their schemas independently (ADR-002).
- Database schema: forward-only migrations; a binary refuses to open a database migrated by a newer binary.
